# Fixes

Bugs found by using the app, most of them during the demo on Leon's MacBook (2026-09-28). Work top to bottom, tick items off, and describe the fix in one line under the item. Every fix starts by reproducing the bug the way a user meets it.

- [x] **Scenario switch shows the wrong scenario.** In Scenarios, switching from Scenario 1 to Scenario 2 leaves every input under it showing the values of Scenario 1. The switch does not work.
      Fixed: the heating inputs, construction choices and GEG check under the Energy panel switch now show the chosen scenario, and edits go into it (the built-in Renovated variant is read only).
      The user's actual bug was in the Scenarios tab: choosing Scenario 2 in the table left the editor below showing Scenario 1 first, because it listed every scenario. Now the editor shows only the scenario chosen in the table, and a rename is kept with a Save button that appears once the name changes.
- [x] **A photo lands on the wrong building.** In the demo: one photo went through "Apply to 3D model" and was applied. Then another building was chosen on the 2D map, its photo was straightened by the AI and its openings drawn, and "Apply to 3D model" put it on the old building. A total disaster in the presentation. The editor must never mix two buildings. Fix it with projects: every building gets its own project, and applying a photo goes into the project of the building it was taken of (see "Projects per building" in IDEAS.md).
      Fixed: every building from the map has its own project; switching leaves the old project first (the address carried `?project=A` to the next building, and the editor then joined A). Manual check pending.
- [x] **Photo editor flashes between two images (kY).** With kY and its photo, after the AI finished, the photo editor flashed very fast between two images and did not show the straightened image correctly. Likely cause: the image size differs from the photo editor size and the layout keeps resizing. Fix: give the photo editor a fixed width that does not depend on the image.
      Fixed: one fixed dialog width; the wall column no longer sizes itself from the image. Manual check pending.
- [ ] **Corners of the chosen wall part.** On kY the middle wall of the street facade was chosen in the 3D map. The AI must know which part of the facade was chosen and find the corners of that middle wall in the photo, not of the whole facade.
      Not fixed yet: a first version was tested on kY and reverted, it cut in the wrong place. The findings and the real plan are in TODO.md, Part 7 X.
- [x] **Plan view lines are invisible (2026-09-29).** In the floor plan view only the arrowheads showed: no dimension lines, extension lines, door swings or window frames. The room label also covered the room's width by height.
      Fixed: the plan group is mirrored (scale z = -1), which flips which side of a mesh counts as front, and drei's fat lines are meshes built in screen space, so every one was culled; this hit every line in the editor (measure tool, drawing previews, pipes, thermal bridges, compass, sun path). All of them now go through `src/scene/Line.tsx`, which draws both sides. The 3D room label is hidden in the plan view, where the plan's own stamp shows name, area and size. Manual check pending.
- [x] **The first SAM 3 detection after a start is slow (2026-09-29).** It took 16.6 s instead of under 2 s. SAM 3 had not changed: the service had just been restarted, and the first pass through the model after a start sets up the graphics card (4.1 s against 0.7 s for "find the wall"), on top of waiting for the model to load.
      Fixed: the service runs one warm-up pass at startup before it says it is ready, so the first photo takes 0.9 s like every later one. Startup takes about 6 s longer.
- [x] **Work turns up in a new project and is saved without asking (2026-09-29).** Leaving the editor asked nothing, the Projects page said "No projects yet", and a new project of the same house showed the floor plan applied before.
      Fixed: a project exists only once it is saved (Save in the project bar, Ctrl+S); leaving unsaved work asks Save, Don't save or Cancel; a new project always starts from a fresh model with no photos, floor plans or undo of another; each project keeps its own photos and floor plan images. See DECISIONS.md. Manual check pending.
- [x] **An interior wall cannot be selected, so it cannot be resized (2026-09-29).** With the select tool a click on an interior wall did nothing visible, and its grips never showed.
      Fixed: the wall selected itself on pointer up, but the click that follows fell through to the room under it (rooms reach under their walls) and selected the room instead; a room now takes a click only when its floor is what was hit. In the floor plan an interior wall also picks along a strip 8 px to each side, since 10 cm is a few pixels. Manual check pending.
- [x] **Interior walls run into the exterior walls, a picked wall runs through several rooms, and its grips do not move (2026-09-29).**
      Fixed: walls are drawn only where they are seen (between the faces they meet, straight through joints, filled at corners); a wall is the piece between two joints, so a pick lights up the wall of that room; a picked wall moves sideways by dragging it instead of by its ends. See DECISIONS.md. Manual check pending.
- [x] **Interior walls poke through the exterior walls in 3D (2026-09-29).** The plan was fixed, the 3D model still built each interior wall over its whole stored length.
      Fixed: the 3D solid is built over the same range the plan draws (between the faces it meets, straight through joints, filled at corners). Only the mesh is cut: the stored walls, openings, rooms, areas and energy figures are unchanged, since nothing that measures uses the solid. Manual check pending.
- [x] **Leaving a building with a photo applied asks nothing, and the work is gone (2026-09-30).** Signed in, BOo chosen, a facade photo applied to the 3D model, then Projects: no "Save this project?", and the Projects page said "No projects yet".
      Fixed: the dialog answered itself. It is shown through `Presence value={answer}`, and `answer` is a function; `usePresence` handed it to React's `useState`, which calls a function as an updater, so React ran `answer(null)` while rendering and the app left as if told to (the "error during concurrent rendering" in the log). `usePresence` now always wraps the value. Reproduced with the whole app, server and account in `src/projects/leave.app.test.tsx`. Two more found on the way: with a server, a copy this browser kept from before counted as a saved project although the Projects page never lists it (now unsaved, and Save makes it a server project), and Ctrl+S threw on key events without a key, which the browser's autofill sends. Manual check pending.
- [x] **A door marked in the photo becomes a window in the 3D model (2026-09-30).** On BOo the photo editor showed two doors (1.25 x 2.69 m and 0.94 x 1.96 m); after Apply to 3D model both were windows.
      Fixed: the photo's bottom edge on that wall sits a little above the street, so the doors' bottoms landed 0.34 m and 0.39 m above the ground floor, and the hand-over turned every door more than 0.30 m above its floor into a window. A door up to 1 m above the floor (entrance steps of an old building) now stays a door, set on the floor at its measured height; up to 0.30 m it still reaches down to the floor as before. Test with the user's own two doors in `lod2-core/test/survey.test.ts`. Manual check pending.
- [x] **3D view: storeys below the edited one look broken, hatched lines and black walls (2026-10-01).** With a storey above the ground floor active, the ground floor drew solid with holes and floating white boxes; zoomed out, hatched stripes ran along every storey line; walls away from the light went almost black, so window reveals looked like damage.
      Fixed: ghost storeys were 15 % transparent and stacked, so a storey with interior walls showed six or more layers on top of each other; they are now opaque and faded toward the background (`scene/ghost.ts`, a halftone as in Revit). The floor slab lay on the outline and shared its outer face with the walls of the storey below; it now lies between the walls' inner faces. Both lights got a shadow bias, the hemisphere light a lighter ground colour and the default light a weak fill from the opposite side. The facade photo ends at the top of the edited storey instead of hanging above it. Checked on screenshots of the user's own BOo project from the angles reported.
- [x] **Project card: the owner badge shows "AD" for Adilzhan, and the view switch reads "G...", "List", "M..." (2026-10-01).**
      Fixed: the card wrote the first two letters of the owner's full name; the server now sends the owner as id, first and last name, and the card uses the shared `Avatar` (first letters of both names, in the person's own colour). The Grid, List, Map switch: the first fix (the row may not squeeze it) did not help, the user still saw "G..." and "M...". The real cause was inside `CustomSegmented`: every option took an equal flex share of a group sized to its content, so the average width cut the longer labels. Text options are now grid columns as wide as the widest label, everywhere the control is used, and still shrink evenly in a narrow panel. Manual check pending.
- [x] **Project card picture: the 3D model shows grid, shadows and whatever the editor view was on (2026-10-01).** The user wants the whole building from a pretty angle, with its wall colour and roof, and nothing else.
      Fixed: the picture is drawn apart from the editor view in a small canvas off the screen (`scene/ModelThumbnail.tsx`): every storey solid, the roof, no ground, grid, map, photos, shadows or selection (`PictureMode` turns selection and hover off in the building's parts). The camera stands in front of the street side (the wall with a facade photo, else the outside wall with the most openings, doors counting more, else the longest outside wall; walls shared with a neighbour never), turned 35 degrees and 24 degrees above, far enough for the whole building with its roof (`geometry/pictureView.ts`, tested). The card now prefers this picture to the facade photo. It is saved as a transparent WebP, so the card's own colour shows behind the building and it follows the light or dark theme (a live 3D view per card was turned down: a WebGL context each, browsers allow about 16). Manual check pending: not seen in a browser.
- [x] **No way to see the building's pictures and files, or to add a photo of another wall (2026-10-01).** The Files tab sat at the far end of the right panel, and a wall photo could only be started from a selected wall's properties.
      Fixed: the layers tree has "Photos and files" for the whole building, under the roof: every outside wall with its facade photo or a way to add one (shared walls say so), the floor plans of all storeys, and the uploaded files with an upload action. Each storey shows its own floor plan as a row too. A click opens the picture or PDF in the middle of the page over the blurred editor (`shared/MediaPreview.tsx` on `CustomDialog`); other files offer a download. The Files tab and the tree share one list (`projects/files.ts`). Found on the way: the running dev server had been started before the Storage key was in `supabase.env`, so every file since then went into the database (`app.file_blobs`, 10 files) instead of Supabase Storage; `npm run dev` now prints where files go, and the server moves them into Storage on its next start. Test in `MediaLayers.test.tsx`. Manual check pending.
- [x] **Clicking a picture in the layers tree only blurs the left panel (2026-10-01).**
      Fixed: the dialog's fixed overlay was rendered inside the panel, which slides in with a transform, so it covered only the panel and the panel clipped the picture. `CustomDialog` now renders into the page body, which fixes every dialog opened from a panel (the History tab's compare had the same fault). The test checks the dialog sits on the body. Manual check pending.
- [x] **Hovering a wall in "Photos and files" shows nothing in the 3D view (2026-10-01).**
      Fixed: hovering (or focusing) a wall's row lights that wall in selection blue on every storey, also on storeys drawn faded or as outlines, and tints its facade photo blue when it has one (`highlightedWall` in the store, UI state only). Test in `MediaLayers.test.tsx`. Manual check pending.
- [x] **Pictures and files do not follow changes (2026-10-01).** A facade photo or floor plan deleted in the Files tab stayed on the wall and in the layers tree until a reload, and a photo, plan or file another person added, replaced or deleted never reached an open tab.
      Fixed: the server announces every file change to the project's tabs ("files" on the socket, `FilesService.events`); each tab reloads its file list (`projects/files.ts`) and its pictures (`projects/photoSync.ts`: a slot gone is taken off its wall or storey, a slot with a new time is fetched again, a picture not uploaded yet stays). Energy, variants, the card's facts and the card picture already follow the building. Tests in `photoSync.test.ts` and `files.test.ts`. Manual check pending.
- [x] **Whole codebase audit (2026-10-01).** Six read-only audits (frontend structure, geometry and energy, backend and API, icons, product and layout, a browser walk-through with about 90 screenshots), then fixes in separate branches, merged and checked. What was wrong, in short:
      Energy: a footprint corner in the middle of an edge dropped that wall's loss (158.65 down to 114.58 W/K on the default building); a heated storey over or under an unheated one lost nothing through the floor or ceiling (now F_x 0.6 and 0.8); L-shaped rooms lost their name and zone on every recompute; a hip roof turned into a gable after a corner was added; footprint edits left facade photos, notes and interior doors on the wrong wall. Backend: an editor removed from a project could keep editing over the socket (reproduced, fixed, tested); a dropped database connection could stop the server; replies reached people removed from the project; reports could start any number of browsers; junk ids gave 500; parallel uploads to one slot failed; the GPU routes were open to anyone (now signed in only, through Caddy). Frontend: loading an example or switching the language inside a shared project overwrote it for everyone; a double save made two projects; one Escape closed stacked dialogs; opening a project from its card dropped it from the address. UI: labels of the 3D view over dialogs, the report printing the app, German data text in English, page titles at body size, the whole app blocked under 1440 px, unreadable class letters, the photo editor deaf to Escape. Each fix has a test; `npm run check` now runs the server too. Details in the commit log of 2026-10-01.
- [x] **Share on the hosted site: "The collaboration server does not answer. Is npm run dev running with its collab line?" (2026-10-02).** Seen right after the site was redeployed; not reproduced afterwards (a project of the same kind saved through the live server with 201, no server errors logged since the restart), so most likely the click fell into the few seconds the server restarts.

Tests in `createProject.test.ts` and `ShareButton.test.tsx`.
